## Теорія

### Чому промптинг — це найважливіший навик

У вайбкодингу якість результату на 80% залежить від якості твого запиту. Один і той самий AI дасть принципово різні результати на різні промпти.

**Поганий промпт:** "Зроби мені сайт"
**Результат:** Щось генеричне, без стилю, без сенсу

**Хороший промпт:** "Створи лендінг для кав'ярні 'Ранкова зірка'. Стиль — мінімалістичний, теплі кольори (бежевий, коричневий). Секції: герой-банер з фото кави, меню (3-4 позиції), відгуки клієнтів, контакти з картою. Мобільна версія обов'язкова."
**Результат:** Конкретний, стилізований, з потрібними секціями

### Як AI "думає" — ментальна модель

AI не "розуміє" як людина. Він передбачує найкращу відповідь на основі контексту. Тому:

1. **Чим більше контексту — тим краще результат**
2. **Конкретність > абстрактність** — "синя кнопка 200px шириною" > "гарна кнопка"
3. **Приклади допомагають** — "як на сайті Apple" дає більше ніж "сучасний дизайн"
4. **AI не читає думки** — якщо ти не сказав, він не здогадається

### 4D — чотири навички роботи з AI

Ефективна робота з Claude будується на чотирьох навичках. Запам'ятай їх — це фундамент всього що буде далі:

| Навичка | Що означає | Приклад |
|---------|-----------|---------|
| **Delegation** (Делегування) | Розумій ЩО варто віддати AI, а що ні | Створити лендінг — так. Придумати бізнес-модель — ні |
| **Description** (Опис) | Вмій чітко описати що ти хочеш | "Синя кнопка 200px" замість "гарна кнопка" |
| **Discernment** (Розсудливість) | Перевіряй результат, не довіряй сліпо | AI каже "готово" — відкрий, клікни, перевір |
| **Diligence** (Старанність) | Ітеруй, уточнюй, не зупиняйся на першому результаті | "Тепер зроби мобільну версію", "Зміни відступи" |

**Delegation** — найважливіший. AI відмінно створює код, пише тексти, аналізує. AI погано придумує за тебе що саме потрібно. Ти — мозок, він — руки.

### Анатомія хорошого промпту

Промпт який стабільно дає якісний результат має **5 компонентів** (з офіційних best practices Anthropic 2026):

```
[МЕТА] — Що потрібно отримати (описуй РЕЗУЛЬТАТ, а не кроки)
[КОНТЕКСТ] — Що вже існує, який проєкт, що зроблено
[ОБМЕЖЕННЯ] — Стиль, технології, що НЕ робити
[ПЕРЕВІРКА] — Як зрозуміти що результат правильний
[ПРИКЛАД] — Як має виглядати результат (референс)
```

**Пункт "Перевірка"** — те що 90% людей пропускають, і що **подвоює якість**. Борис Черні (творець Claude Code) підтверджує: "Дай Claude спосіб перевірити свою роботу — і якість зросте в 2-3 рази."

**Приклад:**

```
МЕТА: Секція з тарифними планами де користувач бачить 3 варіанти 
і може обрати рекомендований.

КОНТЕКСТ: Лендінг для онлайн-курсу з фотографії. 
Вже є header та hero-секція в index.html.

ОБМЕЖЕННЯ: 
- 3 плани: Basic ($29), Pro ($59), Premium ($99)
- Кожен план має 4-5 переваг
- Середній план виділений як "рекомендований"
- Стиль: мінімалістичний, основний колір #2563EB
- Додай прямо в index.html після hero-секції

ПЕРЕВІРКА: Після створення — запусти Live Server 
і переконайся що секція відображається без помилок в консолі.

ПРИКЛАД: Схоже на секцію Pricing на stripe.com — 
чисто, з великими відступами, акцент на середньому плані.
```

**Зверни увагу:** "Перевірка" каже AI перевірити себе самому. Він запустить сервер, подивиться — і якщо щось не так, виправить без твоєї участі.

### 5 правил ефективного промптингу

#### Правило 1: Будь конкретним
```
❌ "Зроби гарну сторінку"
✅ "Зроби сторінку з білим фоном, заголовком по центру 
    шрифтом Inter 48px, та двома колонками тексту під ним"
```

#### Правило 2: Давай контекст
```
❌ "Додай кнопку"
✅ "В секції hero після заголовку додай кнопку 'Спробувати безкоштовно' 
    яка веде на #signup. Стиль як у інших кнопок на сторінці"
```

#### Правило 3: Одна задача за раз
```
❌ "Зроби сайт з авторизацією, дешбордом, профілем та налаштуваннями"
✅ "Зроби сторінку авторизації з формою: email та пароль"
(потім наступний промпт для наступної сторінки)
```

#### Правило 4: Ітеруй
Рідко вдається отримати ідеальний результат з першого разу. Це нормально!

```
Промпт 1: "Створи форму реєстрації"
→ Результат: базова форма

Промпт 2: "Додай валідацію email та мінімальну довжину пароля 8 символів"
→ Результат: форма з валідацією

Промпт 3: "Зроби повідомлення про помилки червоними під полями"
→ Результат: готова форма з валідацією та UX
```

#### Правило 5: Використовуй референси
```
❌ "Зроби сучасний дизайн"
✅ "Зроби дизайн в стилі Stripe.com — чистий, з великими відступами, 
    градієнтний фон, акцент на типографіці"
```

#### Правило 6: Описуй результат, а не кроки
Це одна з найважливіших порад від Anthropic у 2026 році. Не кажи AI **ЯК** робити — кажи **ЩО** має бути в кінці.

```
❌ Кроки (погано): "Додай try-catch блок і обробку помилок"
✅ Результат (добре): "Якщо дані не завантажились — покажи юзеру 
    зрозуміле повідомлення 'Не вдалось завантажити'. 
    Ніколи не показуй білий екран."

❌ Кроки: "Додай media query для мобільного"
✅ Результат: "На телефоні (375px) таблиця має бути читабельною. 
    Якщо не влазить — перетвори в картки або додай горизонтальний скрол."
```

AI видає **набагато кращий** код коли знає що має бути в кінці. Для тебе як непрограміста це ідеально — ти і так думаєш результатами, а не кодом.

#### Правило 7: Додай "а якщо...?"
AI генерує код для ідеального сценарію. Він забуває: що якщо поле пусте? Інтернету нема? Дані не прийшли?

```
❌ "Зроби форму зворотного зв'язку"
✅ "Зроби форму зворотного зв'язку. 
    Також врахуй: що буде якщо юзер залишить поле пустим, 
    що якщо email невалідний, що якщо сервер не відповідає."
```

Одне додаткове речення "а якщо...?" рятує від 80% багів які вилізуть пізніше.

### CLAUDE.md — Інструкція для AI

**CLAUDE.md** — це файл в корені проєкту, який Claude Code читає автоматично при запуску. Це як "бриф" для AI-напарника.

**Навіщо:**
- AI одразу знає контекст проєкту
- Не потрібно повторювати одне й те саме кожну сесію
- Зберігає стиль та конвенції проєкту

**Головне правило: CLAUDE.md має бути коротким** — максимум 1 сторінка (~2500 токенів). Він читається на початку **кожної** сесії і з'їдає контекст. Надто великий файл — поширена помилка яка шкодить якості.

**Приклад CLAUDE.md:**

```markdown
# Мій проєкт: Лендінг для кав'ярні

## Про проєкт
Лендінг для кав'ярні "Ранкова зірка" в Києві.

## Стек
HTML + CSS, мінімалізм, мобільна адаптивність.

## Стиль
Кольори: бежевий (#F5F0E8), коричневий (#6B4423), білий.
Шрифти: Inter (текст), Playfair Display (заголовки).

## Правила
- Все українською мовою
- Семантичний HTML
- Якщо не впевнений в бібліотеці — скажи, не вигадуй
- Якщо не знаєш відповіді — скажи "не знаю"

## Виучені уроки
- Не використовувати position: fixed для мобільного меню — ламає скрол
- Зображення завжди через <img> з alt, не через background-image
```

**Зверни увагу на секцію "Виучені уроки"** — це трюк від досвідчених вайбкодерів: коли Claude робить одну й ту ж помилку повторно, додаєш рядок в CLAUDE.md. З часом файл "вчиться" і помилки зникають.

**Рядки "якщо не впевнений — скажи"** — це 3 анти-галюцинаційні промпти з офіційної документації Anthropic. Вони "драматично" знижують кількість вигадок AI. Додай їх в кожен проєкт.

**Ретро в кінці сесії:** Перед тим як закінчити роботу, спитай Claude: *"Що ти дізнався під час цієї сесії? Які помилки були? Що варто додати в CLAUDE.md?"* — і збережи корисне. Так проєкт стає розумнішим з кожною сесією.

> **CLAUDE.local.md** — персональний файл який НЕ потрапляє в Git. Сюди — особисті нотатки, WIP-замітки, шляхи до файлів на твоєму комп'ютері. Формат такий самий як CLAUDE.md.

### Типові помилки новачків

| Помилка | Чому погано | Як правильно |
|---------|------------|--------------|
| "Зроби все красиво" | AI не знає що "красиво" для тебе | Опиши конкретний стиль або дай референс |
| Величезний промпт на 20 задач | AI заплутається або щось пропустить | Розбий на кроки, одна задача за раз |
| Не дивитися результат | Помилки накопичуються | Перевіряй після кожного кроку |
| Починати з нуля при помилці | Втрачаєш прогрес | Попроси виправити конкретну проблему |
| Не давати контекст | AI щоразу "забуває" | Використовуй CLAUDE.md |

### Коли AI дає не те — що робити

Рано чи пізно ти напишеш промпт, а у відповідь отримаєш щось настільки далеке від очікуваного, що захочеш вимкнути комп'ютер. Це нормально. Ось як з цим працювати:

#### Ситуація 1: AI зробив не те, що ти просив

**Причина:** Промпт був неоднозначним, і AI інтерпретував по-своєму.

```
❌ Ти: "Зроби таблицю з даними"
   AI: *створює HTML таблицю з випадковими числами*
   
✅ Ти: "Створи таблицю конкурентів Amazon зі стовпцями: 
   назва, бренд, ціна, BSR, revenue, зміна за день (%).
   10 рядків з реалістичними даними. Стиль: Tailwind,
   зебра-стрічки, числа вирівняні праворуч."
```

**Рішення:** Додай конкретику. Чим точніший запит — тим ближче результат.

#### Ситуація 2: AI генерує код який не працює

**Причина:** Неправильна бібліотека, застарілий синтаксис, або конфлікт з існуючим кодом.

```
Ти: "Додай графік з Chart.js"
AI: *пише код з Chart.js v2 синтаксисом, а встановив v4*
→ Нічого не працює
```

**Рішення:** 
1. Покажи помилку: "Ось помилка з консолі: [текст]. Виправ."
2. Вкажи версію: "Використай Chart.js v4 або recharts (останню версію)"
3. Попроси пояснити перед тим як робити: "Яку бібліотеку для графіків ти б використав в Next.js? Поясни чому. Потім реалізуй."

#### Ситуація 3: AI зробив, але виглядає жахливо

**Причина:** Не дав дизайн-контекст.

**Рішення:** Дай референс ([[04-first-project|модуль 4]]) або опиши стиль детальніше. AI за замовчуванням робить "щось робоче", а не "щось гарне".

#### Ситуація 4: AI "галюцинує" — вигадує неіснуюче

**Це найважливіше що потрібно знати про AI.** Навіть у 2026 році найкращі моделі галюцинують у 4-19% випадків. Claude — один з найкращих, але все одно вигадує.

**Найчастіша проблема в коді (65% всіх помилок AI)** — phantom imports: AI вигадує бібліотеку або функцію яка звучить правдоподібно, але не існує.

**Реальні кейси:**
```
❌ AI написав: import { useAuth } from 'next-auth-helpers'
   Проблема: Бібліотека next-auth-helpers не існує

❌ AI написав: await prisma.$upload(file)
   Проблема: Метод $upload() в Prisma не існує — AI вигадав

❌ AI написав: import Chart from 'react-simple-charts'
   Проблема: Пакет є, але давно заброшений і не працює
```

**Чому AI це робить:** Він не "знає" бібліотеки — він передбачує що звучить правдоподібно. `prisma.$upload()` звучить логічно, тому AI впевнено його пропонує.

**Як захиститись — 3 рядки в CLAUDE.md:**
```
- Якщо не впевнений в бібліотеці або методі — скажи, не вигадуй
- Якщо не знаєш відповіді — скажи "не знаю"
- Використовуй тільки ті бібліотеки які точно існують і підтримуються
```

Ці три інструкції з офіційної документації Anthropic "драматично" знижують галюцинації.

**Практичне правило:** Якщо AI пропонує бібліотеку або метод який ти не бачив раніше — 5 секунд гуглу або `npm search назва`. Дешевше ніж 30 хвилин дебагу вигаданого коду.

#### Ситуація 5: Розмова "пішла не туди"

Ти 10 промптів намагаєшся отримати потрібний результат, AI з кожним разом все далі від мети.

**Рішення:**
```bash
# В Claude Code:
/clear
```
Почни з чистого аркуша. Новий промпт, з нуля, чітко. Іноді це ефективніше ніж ще 10 спроб "виправити".

#### Ситуація 6: AI робить занадто багато

Ти попросив змінити колір кнопки, а AI переписав половину компонента.

**Рішення:** Будь конкретним щодо ОБСЯГУ змін:
```
Зміни ТІЛЬКИ колір кнопки "Submit" з синього на зелений.
Більше НІЧОГО не міняй.
```

### Коротко — чек-лист "AI дає не те"

```
□ Промпт достатньо конкретний? → Додай деталі
□ Дав контекст проєкту? → CLAUDE.md, DESIGN.md
□ Показав референс? → Скріншот, приклад
□ Помилка в коді? → Покажи текст помилки AI
□ 3+ спроби безрезультатно? → /clear, починай з нуля
□ AI вигадує? → Перевір, попроси джерело
□ Змінює забагато? → Обмеж обсяг явно
```

## Практика

### Завдання 1: Від поганого до ідеального (20 хв)

Візьми цей поганий промпт та покращуй його крок за кроком:

**Стартовий промпт:** "Зроби мені сайт"

**Крок 1:** Додай конкретику — що за сайт?
**Крок 2:** Додай контекст — для кого, навіщо?
**Крок 3:** Додай деталі — стиль, кольори, секції
**Крок 4:** Додай формат — технологія, обмеження
**Крок 5:** Додай референс — на що має бути схоже

Запусти фінальний промпт в Claude Code та подивись результат.

### Завдання 2: Створи CLAUDE.md (10 хв)

1. Придумай простий проєкт
2. Створи файл CLAUDE.md з описом:
   - Про проєкт (2-3 речення)
   - Стек (що використовуємо)
   - Стиль (кольори, шрифти)
   - Структура (які сторінки/секції)
   - Важливо (обмеження)
3. Запусти Claude Code в цій папці — він одразу "знатиме" про проєкт

### Завдання 3: Ітеративна розробка (15 хв)

1. Попроси Claude Code створити просту картку товару
2. Подивись результат в браузері
3. Напиши 5 послідовних промптів щоб покращити її:
   - Змінити кольори
   - Додати кнопку "Купити"
   - Додати зображення
   - Зробити тінь та заокруглення
   - Додати hover-ефект

Зверни увагу як кожен крок будує на попередньому результаті.

## Питання для самоперевірки

1. Ти написав промпт "Зроби таблицю". AI створив таблицю множення. Де проблема?

2. Ти 4 рази попросив AI виправити один і той самий компонент — кожен раз стає гірше. Найкращий наступний крок?

3. CLAUDE.md — це файл який AI читає при старті. Якщо ти описав в ньому "стиль — мінімалістичний, кольори — синій та білий", то при запиті "створи нову сторінку" AI вже знає...

4. AI вигадав бібліотеку `super-charts-pro` яка не існує в npm. Як перевірити і що робити?

5. Промпт "Зроби лендінг як у Apple" краще ніж "зроби сучасний лендінг" тому що...
