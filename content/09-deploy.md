## Теорія

### Що таке деплой

**Деплой (deploy)** — це публікація твого проєкту в інтернеті, щоб інші люди могли ним користуватись.

```
Зараз:                          Після деплою:
localhost:3000                   https://my-mvp.vercel.app
(бачиш тільки ти)               (бачить вся команда)
```

До цього моменту все працювало тільки на твоєму ноутбуці. Після деплою — відправив посилання колезі, і він одразу бачить робочий продукт. Магія? Ні, просто правильний workflow.

### Хостинг — де живе сайт

**Хостинг** — це сервер (комп'ютер) який працює 24/7 і показує твій сайт всім хто заходить.

Ми надаємо доступ до хостингу та сервера — тобі не потрібно нічого купувати чи налаштовувати самостійно.

| Сервіс | Для чого | Наш кейс |
|--------|----------|----------|
| **Vercel** | Next.js, React, статичні сайти | Веб-додатки, дешборди |
| **Railway** | Бекенд, бази даних, боти | Python-скрипти, Telegram-боти |
| **Supabase** | База даних, авторизація | Зберігання даних |

### Vercel — деплой за 3 кліки

**Vercel** — платформа від творців Next.js:
- Автоматичний деплой при git push
- HTTPS за замовчуванням (безпечне з'єднання)
- CDN по всьому світу (сайт швидкий для всіх)
- Preview для кожного бранча — можеш показати зміни до того, як вони потраплять у продакшн

**Як працює:**
```
git push → Vercel бачить зміни → Збирає проєкт → Публікує
                                                    ↓
                                          https://my-mvp.vercel.app
```

Пушнув зміну — через хвилину вона вже в інтернеті. Без магії, без серверів, без DevOps-інженера.

### Змінні середовища (Environment Variables)

Пам'ятаєш .env.local з [[07-data|модуля 7]]? Ці ключі потрібно також додати на хостинг:

```
NEXT_PUBLIC_SUPABASE_URL=https://xxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOiJ...
```

**Чому не можна просто закомітити .env.local:**
- .env.local в .gitignore — не потрапляє в GitHub
- Секрети в коді = загроза безпеці (API-ключ до бази конкурентів в публічному репозиторії — не найкраща ідея)
- Хостинг має свій інтерфейс для змінних середовища

### Домен — красива адреса

За замовчуванням отримаєш адресу `project-name.vercel.app`. Для внутрішніх інструментів компанії це часто достатньо. Для клієнтських продуктів — підключаємо свій домен.

## Практика

### Крок 1: Підготовка проєкту (10 хв)

Перед деплоєм переконайся що все працює локально:

```
Перевір мій проєкт перед деплоєм:
1. Запусти build: npm run build
2. Якщо є помилки — виправ їх
3. Запусти production-версію: npm start
4. Перевір що всі сторінки працюють
5. Переконайся що .gitignore включає node_modules та .env.local
```

### Крок 2: GitHub репозиторій (5 хв)

Якщо проєкт ще не на GitHub:

```bash
# Створити репозиторій на GitHub (через gh CLI або веб)
gh repo create my-mvp --public --source=. --push
```

Або вручну:
1. GitHub.com → New Repository
2. Назва: my-mvp
3. Public
4. Не додавай README
5. Скопіюй команди для push existing repo

### Крок 3: Деплой на Vercel (10 хв)

1. Відкрий https://vercel.com
2. "Sign Up" через GitHub
3. "Add New Project"
4. Обери свій репозиторій
5. Vercel автоматично визначить Next.js
6. Натисни "Deploy"
7. Зачекай 1-2 хвилини

Після деплою отримаєш посилання виду: `https://my-mvp-abc123.vercel.app`

### Крок 4: Змінні середовища (5 хв)

1. В Vercel Dashboard → Settings → Environment Variables
2. Додай всі змінні з .env.local
3. Натисни "Redeploy" щоб зміни застосувались

### Крок 5: Перевірка (5 хв)

Відкрий свій сайт та перевір:
- [ ] Головна сторінка завантажується
- [ ] Навігація між сторінками працює
- [ ] Дані завантажуються та відображаються
- [ ] Фільтри та порівняння працюють
- [ ] Мобільна версія виглядає прийнятно

### Крок 6: Покажи команді (5 хв)

1. Скопіюй URL
2. Відправ в командний чат
3. Попроси 2-3 людини протестувати
4. Запиши їхній feedback — це найцінніше що можна отримати від MVP

## Типові проблеми

| Проблема | Рішення |
|----------|---------|
| Build fails на Vercel | Перевір чи `npm run build` працює локально |
| Сторінка показує помилку | Перевір Environment Variables |
| Дані не завантажуються | API ключі додані на хостинг? |
| 404 на сторінках | Перевір структуру папок в app/ |
| Довго деплоїться | Перевір розмір проєкту, можливо великі файли в git |

## Питання для самоперевірки

1. До деплою твій MVP працює на `localhost:3000`. Це бачиш тільки ти. Після деплою — це `https://my-mvp.vercel.app`. Різниця в тому що...

2. `npm run build` показує помилки, але `npm run dev` працює нормально. Чому потрібно виправити build-помилки перед деплоєм?

3. В .env.local є `SUPABASE_ANON_KEY=eyJhbGci...`. Ти задеплоїв, але дані не завантажуються. Найімовірніша причина?

4. Ти зробив `git push` і через хвилину зміни вже на сайті. Це працює тому що...

5. Ти задеплоїв MVP і відправив посилання 3 колегам. Один каже "таблиця незрозуміла", інший — "додай фільтр по датах". Це найцінніший результат MVP тому що...
