# Модуль 3A: Дебагінг — Коли щось пішло не так

> **Тривалість:** 20 хв теорія + 20 хв практика
> **Результат:** Навичка спокійно вирішувати проблеми та не панікувати

---

## Теорія

### Помилки — це нормально

Ось правда яку ніхто не каже новачкам: **професійні розробники витрачають 30-50% часу на дебагінг.** Не тому що вони погані — тому що помилки неминучі.

У вайбкодингу помилки бувають ще частіше, бо AI може:
- Неправильно зрозуміти що ти хочеш
- Згенерувати код з багом
- Зламати одне, виправляючи інше
- Використати застарілий підхід

Це не привід панікувати. Це привід мати систему для вирішення проблем.

### Золоте правило дебагінгу

> **Зупинись. Прочитай. Подумай. Тоді дій.**

Найпоширеніша помилка новачка — панічно тикати, просити AI "виправ!!", і робити ще гірше. Кожна нова "спроба виправити" без розуміння проблеми — це новий шар проблем.

### Коли треба взяти паузу

```
⚠️ СИГНАЛИ ЩО ТРЕБА ЗУПИНИТИСЬ:

□ Ти 3+ рази попросив AI виправити одне й те саме
□ Кожне "виправлення" створює нову помилку
□ Ти не розумієш що саме зламалось
□ Ти починаєш злитися на комп'ютер
□ Ти хочеш видалити все і почати з нуля
```

Якщо хоча б 2 пункти — **СТОП**. Відійди на 5 хвилин. Випий кави. Серйозно.

Після паузи:
1. Відкотись до останнього робочого стану
2. Чітко сформулюй що пішло не так
3. Попроси AI пояснити, а не виправити
4. Зроби одну маленьку зміну і перевір

### Правило двох спроб

> **Після 2 невдалих спроб виправити — завжди відкочуйся.**

Це не порада, це правило. Reddit-спільнота вайбкодерів (2026) одностайна: третя спроба "виправити" майже ніколи не працює. Кожна невдала спроба **забруднює контекст** — AI починає "тягнути" невдалий код з попередніх спроб.

```
Спроба 1: AI спробував виправити → не вийшло
Спроба 2: AI спробував інакше → стало гірше
Спроба 3: ❌ НЕ РОБИ. Контекст уже забруднений.

Замість цього:
  /rewind       ← відкочує код І розмову (чистить контекст)
  або
  /clear        ← повний reset, новий промпт з нуля
```

**Чому `/rewind` краще ніж `git checkout .`?**
`git checkout .` відкотить файли, але контекст розмови залишиться забрудненим. `/rewind` відкочує і код, і розмову — AI "забуває" невдалі спроби.

### Типи помилок та як їх вирішувати

#### Тип 0: Забруднений контекст ("Kitchen Sink Session")

Це найпідступніший тип проблем — технічно помилки немає, але AI починає працювати гірше.

**Симптоми:**
- AI "тупіє" — дає гірші відповіді ніж на початку
- Повторює ті ж помилки які ти вже просив виправити
- Починає додавати код який ти не просив
- Відповіді стають довшими і менш релевантними

**Причина:** Ти змішав кілька різних задач в одній сесії, або контекст переповнений невдалими спробами.

```
❌ "Kitchen sink session" (все в одній розмові):
   "Створи форму" → "Виправ навігацію" → "А яка столиця Франції?" 
   → "Тепер зроби таблицю" → AI плутається і робить гірше

✅ Одна сесія = одна задача:
   Сесія 1: Створити форму → /clear
   Сесія 2: Виправити навігацію → /clear  
   Сесія 3: Зробити таблицю
```

**Що робити:**
1. `/compact` — якщо працюєш над однією задачею і контекст просто довгий
2. `/clear` — якщо змішав кілька задач або AI "застряг"
3. Почни нову сесію з чітким промптом

#### Тип 1: Помилка в терміналі (build error)

```
Error: Cannot find module './components/Header'
```

**Що робити:**
1. **Прочитай повідомлення** — воно зазвичай каже що не так
2. "Cannot find module" = файл не існує або шлях неправильний
3. Попроси AI: "Ось помилка: [вставь текст]. Що це означає і як виправити?"

**Кейс:**
```
❌ Ти: "Виправ помилку"
   AI: *щось робить, може навіть гірше*

✅ Ти: "Ось помилка: Cannot find module './components/Header'. 
   Перевір чи файл Header.tsx існує, і чи правильний шлях імпорту."
   AI: *знаходить що файл називається header.tsx (мала літера)*
```

#### Тип 2: Сторінка не відображається (білий екран)

**Що робити:**
1. Відкрий DevTools: F12 або Ctrl+Shift+I
2. Перейди на вкладку Console
3. Побач червоні помилки
4. Скопіюй текст помилки
5. Попроси AI: "Біла сторінка, в консолі: [помилка]. Як виправити?"

#### Тип 3: Виглядає не так як треба (CSS/стилі)

```
Очікував: картки в ряд по 3
Отримав: картки одна під одною
```

**Що робити:**
1. Відкрий DevTools → вкладка Elements
2. Наведи на елемент — побачиш його CSS
3. Скажи AI: "Секція з картками. Зараз картки йдуть вертикально. 
   Потрібно 3 в ряд на десктопі, 1 на мобільному."
4. Дай скріншот якщо можеш

#### Тип 4: Дані не завантажуються

**Що робити:**
1. DevTools → Network → перезавантаж сторінку
2. Шукай червоні запити
3. Клікни на запит → Response → побач що повернув сервер
4. Типові причини:
   - API ключ невірний або відсутній
   - URL невірний
   - CORS помилка (сервер блокує запит з браузера)

```
✅ Промпт: "Дані з Supabase не завантажуються. 
   В Network tab бачу 401 Unauthorized. 
   Перевір чи правильний SUPABASE_ANON_KEY в .env.local"
```

#### Тип 5: "Працювало, а тепер ні"

Найфрустрируюча ситуація. Ти нічого не міняв (здається), а воно зламалось.

**Що робити:**
```bash
# 1. Подивись що змінилось
git diff

# 2. Якщо є зміни — можливо AI щось зачепив
git stash              # Тимчасово прибрати зміни
# Перевірити — працює? 
git stash pop          # Повернути зміни

# 3. Якщо змін немає — можливо проблема зовнішня
# Перезапусти dev-сервер: Ctrl+C, потім npm run dev
# Очисти кеш: rm -rf .next && npm run dev
```

### Кейси з реальними помилками

#### Кейс 1: Зациклений фікс

```
❌ НЕПРАВИЛЬНО:

Ти: "Додай фільтр по даті"
AI: *додає фільтр, зламує таблицю*
Ти: "Виправ таблицю"
AI: *виправляє таблицю, зламує фільтр*
Ти: "Виправ фільтр"
AI: *виправляє фільтр, знову зламує таблицю*
... нескінченний цикл ...

✅ ПРАВИЛЬНО:

Ти: "Додай фільтр по даті"
AI: *додає фільтр, зламує таблицю*
Ти: "Стоп. git checkout ."  ← відкотився
Ти: "Я хочу додати фільтр по даті до таблиці конкурентів.
     Таблиця зараз працює. Додай фільтр БЕЗ зміни 
     існуючої логіки таблиці. Фільтр має бути окремим 
     компонентом який передає параметри в таблицю."
AI: *робить правильно, бо зрозумів контекст*
```

#### Кейс 2: Незрозуміла помилка

```
Помилка: "Hydration mismatch"

❌ НЕПРАВИЛЬНО:
Ти: "Виправ hydration mismatch"
AI: *починає переписувати компонент, ламає ще більше*

✅ ПРАВИЛЬНО:
Ти: "Поясни що таке Hydration mismatch в Next.js. 
     Не виправляй поки що — просто поясни причини."
AI: "Це коли HTML на сервері відрізняється від HTML в браузері.
     Часті причини: дата/час, window/document, рандомні значення"
Ти: "Зрозумів. Перевір мій компонент [назва] на ці причини 
     і покажи де саме проблема."
AI: *знаходить Date.now() в рендері*
```

#### Кейс 3: Після оновлення все зламалось

```
Ти оновив бібліотеку і все впало.

❌ НЕПРАВИЛЬНО:
Видалити node_modules, npm install, і молитися.

✅ ПРАВИЛЬНО:
1. git diff package.json  ← що змінилось?
2. git checkout -- package.json package-lock.json  ← повернути
3. npm install  ← відновити старі версії
4. Тепер оновлювати по одній бібліотеці за раз
```

### DevTools — мінімум який потрібно знати

DevTools (F12) — це твої очі всередині браузера:

![[Screenshot_167.png]]

| Вкладка | Навіщо | Коли використовувати |
|---------|--------|---------------------|
| **Console** | Показує помилки JavaScript | Біла сторінка, щось не працює |
| **Elements** | Показує HTML та CSS елементів | Стилі не такі як очікувалось |
| **Network** | Показує запити до API | Дані не завантажуються |
| **Application** | LocalStorage, cookies | Проблеми з авторизацією |

Не потрібно знати DevTools глибоко. Достатньо:
1. Відкрити
2. Побачити червоний текст = помилка
3. Скопіювати текст помилки
4. Показати AI

### Чекліст верифікації AI-результату

AI зробив зміни? Перед тим як сказати "ок, далі" — перевір по 5 пунктах:

```
□ 1. ПРАЦЮЄ?     — Відкрий в браузері, клікни по основному сценарію
□ 2. НЕ ЗЛАМАВ?  — Перевір що старий функціонал теж працює
□ 3. ЧИСТО?      — git diff: чи немає зайвих змін в файлах 
                   які ти не просив змінювати?
□ 4. РЕАЛЬНО?    — Якщо AI додав import або бібліотеку — 
                   вона дійсно існує? (phantom imports!)
□ 5. ЗРОЗУМІЛО?  — Ти розумієш ЩО було змінено? 
                   Якщо ні — попроси пояснити перед тим як рухатись далі
```

**Пункт 4 — найважливіший.** AI може "вигадати" бібліотеку яка не існує (phantom import). Якщо бачиш незнайомий пакет — загугли його перед `npm install`.

## Практика

### Завдання 1: Навмисно зламай і виправ (10 хв)

1. Відкрий будь-який робочий проєкт
2. Зроби коміт "Перед експериментом — все працює"
3. Попроси Claude Code: "Видали один важливий імпорт з головної сторінки"
4. Подивись на помилку в браузері
5. Відкрий DevTools Console — скопіюй помилку
6. Покажи помилку Claude Code та попроси пояснити
7. Виправ
8. Або просто: `git checkout .`

### Завдання 2: Кейс з зацикленням (10 хв)

1. Попроси AI зробити складну зміну
2. Якщо щось зламалось — **НЕ проси "виправ"**
3. Замість цього:
   - Відкотись: `git checkout .`
   - Розбий задачу на менші кроки
   - Виконай перший крок → перевір → коміт
   - Другий крок → перевір → коміт
   - І так далі

## Шпаргалка: Перша допомога при помилках

```
БІЛА СТОРІНКА:
  1. F12 → Console → скопіювати помилку
  2. Показати AI → попросити пояснити
  3. Виправити одну річ → перевірити

ДАНІ НЕ ЗАВАНТАЖУЮТЬСЯ:
  1. F12 → Network → знайти червоний запит
  2. Перевірити .env.local → чи є всі ключі
  3. Перевірити URL API → чи правильний

СТИЛІ ЗЛАМАНІ:
  1. F12 → Elements → навести на елемент
  2. Побачити які CSS-класи → що не так
  3. Скріншот AI → попросити виправити

ВСЕ ЗЛАМАЛОСЬ:
  1. git checkout .     ← повернути все як було
  2. Зробити менший крок
  3. Перевірити → комітити → наступний крок

AI ЗАЦИКЛИВСЯ:
  1. /clear             ← очистити контекст
  2. Переформулювати задачу з нуля
  3. Дати більше контексту і обмежень
```

## Питання для самоперевірки

1. Ти побачив білу сторінку замість свого дешборду. Перша дія — панічно просити AI "виправ все!" чи...?

2. Ти 4 рази попросив AI виправити навігацію — кожен раз стає гірше. Це типова ситуація "зацикленого фіксу". Правильна дія — п'ятий раз попросити "виправ" чи...?

3. Помилка в терміналі: `Cannot find module './components/Header'`. Що це означає простими словами?

4. В Network tab DevTools ти бачиш червоний запит з кодом 401. Найімовірніша причина?

5. Ти 3 рази підряд просиш AI виправити одне й те саме, починаєш злитися. Згідно модуля, коли з'являються 2+ сигнали зі списку "коли треба зупинитись" — потрібно...
