# Модуль 1: Знайомство з Claude — Інтерфейс та можливості

> **Тривалість:** 20 хв теорія + 20 хв практика
> **Результат:** Розуміння інтерфейсу Claude, моделей, режимів роботи

---

## Теорія

### Claude — хто це і навіщо

**Claude** — це AI-модель від компанії Anthropic. Головний інструмент цього курсу — **Claude Code**, який працює в терміналі.

| Інтерфейс | Де | Для чого |
|------------|---|----------|
| **Claude Code** | Термінал | Створення та редагування файлів проєкту — **основний інструмент курсу** |
| **claude.ai** | Браузер | Чат, питання, генерація тексту |
| **Cursor** | Редактор коду | Опціонально — зручно бачити код та файли візуально |
| **API** | Для розробників | Інтеграція в свої продукти |

**Весь курс можна пройти тільки з Claude Code + браузер.** Ти описуєш що хочеш в терміналі, Claude створює файли, ти перевіряєш результат в браузері. Cursor — це додатковий комфорт для тих хто хоче бачити структуру проєкту і код візуально.

### Моделі — що це таке

Модель — це "мозок" AI. Різні моделі мають різні можливості:

| Модель | Характеристика | Коли використовувати |
|--------|---------------|---------------------|
| **Claude Opus** | Найрозумніший, але повільніший | Складні задачі, архітектура, рефакторинг |
| **Claude Sonnet** | Баланс швидкості та якості | Основна робота — генерація коду, правки |
| **Claude Haiku** | Найшвидший, простіший | Прості правки, відповіді на питання |

**Для вайбкодингу** здебільшого використовуємо Sonnet — це оптимальний баланс. Якщо задача складна і Sonnet не справляється — переключаємось на Opus.

Не переживай щодо вибору — за замовчуванням стоїть правильна модель. Якщо щось не виходить, просто попроси "використай розумнішу модель" і переключи.

### Cursor — опціональний візуальний редактор

**Cursor** — це редактор коду з вбудованим AI. Він НЕ обов'язковий для курсу, але може бути зручним.

**Коли Cursor корисний:**
- Хочеш бачити дерево файлів проєкту візуально (sidebar зліва)
- Хочеш бачити та розуміти код який Claude написав
- Швидка правка одного рядка — виділив, Ctrl+K, 

**Коли Cursor НЕ потрібний:**
- Тобі не цікаво що в коді — головне щоб працювало
- Всю роботу робиш через Claude Code в терміналі
- Результат перевіряєш в браузері

![[Cursor-AI-Interface--Explained-in-Detail.webp]]

**Все що робить Cursor — Claude Code робить через чат:**

| В Cursor | В Claude Code (без Cursor) |
|----------|---------------------------|
| Sidebar — бачиш файли проєкту | "Покажи структуру проєкту" або `ls` |
| Ctrl+K — виділив код, описав правку | "В файлі header.tsx зміни колір на синій" |
| Ctrl+L — відкрив чат, питаєш | Просто пишеш питання прямо в терміналі |
| Клік на файл — бачиш код | "Покажи вміст файлу index.html" |
| Зберегти файл — Ctrl+S | Claude зберігає автоматично при редагуванні |

Різниця лише в тому, що в Cursor ти **бачиш** код візуально, а в Claude Code ти **описуєш** що хочеш змінити. Результат однаковий — відкриваєш браузер і перевіряєш.

**Якщо все ж використовуєш Cursor — додаткові можливості:**

| Спосіб | Як | Коли |
|--------|-----|------|
| **Ctrl+K** (inline) | Виділив код → описав правку | Швидкі зміни: "зроби кнопку синьою" |
| **Ctrl+L** (чат) | Відкриває AI-чат збоку | Обговорити підхід, попросити пояснення |
| **Claude Code** (термінал) | Ctrl+` → `claude` | Основна робота: створення, редагування, команди |

### Claude Code — як працює

Запускаєш в терміналі:
```bash
claude
```

Після цього ти в "розмові" з AI. Він бачить всі файли проєкту і може:

| Можливість         | Приклад                                       |
| ------------------ | --------------------------------------------- |
| Створювати файли   | "Створи сторінку контактів"                   |
| Редагувати існуючі | "В header.tsx зміни колір на синій"           |
| Видаляти           | "Видали файл old-page.tsx"                    |
| Запускати команди  | "Запусти npm install axios"                   |
| Пояснювати         | "Поясни що робить цей файл"                   |
| Шукати             | "Знайди де використовується компонент Button" |

#### Вкладки та можливості Claude Code

**Контекст проєкту:**
Claude Code при запуску автоматично "бачить" структуру проєкту. Він знає які файли є, яка архітектура, який стек. Не потрібно кожен раз пояснювати "у мене Next.js проєкт з Tailwind".

**CLAUDE.md:**
Файл-інструкція в корені проєкту. Claude Code читає його першим при старті. Тут зберігаєш стиль, конвенції, важливі рішення.

**Slash-команди:**
- `/help` — показати доступні команди
- `/clear` — очистити контекст (почати "з чистого аркуша")
- `/compact` — стиснути контекст якщо розмова довга
- `/rewind` (або ESC ESC) — відкотити код І розмову до попереднього стану
- `/review` — Claude перевіряє свій код на баги та проблеми
- `/simplify` — Claude прибирає зайву складність з написаного коду

**Автоматичні checkpoints:**
Claude Code автоматично зберігає стан коду перед кожним редагуванням. Навіть якщо ти забув зробити git commit — checkpoint вже є. `/rewind` поверне до будь-якого з них. Це не заміна Git (який зберігає історію назавжди), а страховка "тут і зараз".

**Типовий workflow — "Explore → Plan → Code → Commit":**

Це офіційний підхід Anthropic до роботи з Claude Code. Чотири кроки, кожен обов'язковий:

```
EXPLORE  → Розберись в задачі. Claude читає проєкт, ти описуєш контекст.
PLAN     → Попроси план перед кодом. "Спочатку покажи що будеш робити."
CODE     → Claude пише код. Ти перевіряєш результат в браузері.
COMMIT   → Працює? Комітни. Зламалось? /rewind і новий промпт.
```

**На практиці це виглядає так:**
```
1. Відкрив термінал → claude
2. [EXPLORE]  "Подивись на проєкт. Що вже є?"
3. [PLAN]     "Хочу додати форму зворотного зв'язку. Покажи план."
4. [CODE]     "Ок, реалізуй" → перевірив в браузері
5. [COMMIT]   git add . && git commit -m "Add contact form"
6. Наступна задача → повторюємо цикл
```

**Чому саме такий порядок:**
- **Explore** без нього — Claude не знає контекст, генерує щось від себе
- **Plan** без нього — Claude одразу кодить, може піти в неправильному напрямку
- **Code** без перевірки — баги накопичуються непомітно
- **Commit** без нього — зламаєш все і немає куди відкотитись

### Коли що використовувати

| Ситуація | Інструмент | Чому |
|----------|-----------|------|
| Потрібна нова сторінка/компонент | Claude Code | Бачить весь проєкт, створить файл в правильному місці |
| Запустити команду | Claude Code | Може сам запустити npm install, git push |
| Обговорити підхід, спланувати | Claude Code | Попроси "спочатку план, потім код" |
| Не розумію що робить код | Claude Code | "Поясни що робить файл X" |
| Швидка правка в одному файлі | Cursor Ctrl+K *(якщо встановлений)* | Виділив → описав → готово |

### Контекст — головний ресурс який треба берегти

Claude Code тримає в пам'яті всю вашу розмову — це називається **контекстне вікно**. Уяви робочий стіл: чим більше на ньому паперів, тим складніше знайти потрібний. З контекстом AI так само.

**Чому це важливо:**
- Чим довша розмова — тим "тупіше" стає AI (він губиться в обсязі)
- Якщо в контексті залишився невдалий код — AI "тягне" його в нові спроби
- Мікс різних задач в одній сесії забруднює контекст

**Як правильно управляти контекстом:**

```
ОДНА СЕСІЯ = ОДНА ЗАДАЧА

✅ Правильно:
   Сесія 1: Створити форму зворотного зв'язку → /clear
   Сесія 2: Виправити навігацію → /clear
   Сесія 3: Додати фільтри до таблиці

❌ Помилка ("kitchen sink session"):
   "Створи форму... а ще, яка столиця Франції?... 
    а тепер виправ навігацію..." 
   → Контекст забруднений, AI плутається
```

**Коли що використовувати:**

| Ситуація | Команда | Що робить |
|----------|---------|-----------|
| Переключаєшся на іншу задачу | `/clear` | Повне очищення — чистий аркуш |
| Довга сесія, AI "тупіє" | `/compact` | Стискає розмову, зберігає суть |
| AI написав фігню, хочеш відкотитись | `/rewind` | Повертає код І розмову назад |
| Все пішло не так, 2+ спроби виправити | `/clear` + новий промпт | Починаєш з нуля з кращим промптом |

**Золоте правило:** `/compact` коли працюєш довго над одним, `/clear` коли переключаєшся.

### Поради для ефективної роботи

1. **Не починай з нуля кожну сесію** — Claude Code пам'ятає контекст проєкту через CLAUDE.md
2. **Один запит = одна задача** — не проси 10 речей одночасно
3. **Перевіряй результат після кожного кроку** — баги накопичуються
4. **Якщо AI "застряг"** — переформулюй запит або дай більше контексту
5. **Короткі сесії > довгі марафони** — 30 хвилин фокусу ефективніші за 3 години "обо всьому"
6. **Два рази не вийшло → відкотись** — `/rewind` і новий промпт краще ніж третя спроба "виправ"

## Практика якщо вибрали Cursor
### Завдання 1: Перший запуск Claude Code (10 хв)

1. Відкрий термінал
2. Створи папку і зайди в неї: `mkdir test-project && cd test-project`
3. Запусти `claude`
4. Попроси: "Створи файл index.html з заголовком 'Привіт, я вайбкодер!'"
5. Відкрий файл в браузері — побач результат
6. Попроси: "Додай кнопку яка змінює колір фону"
7. Оновлюй сторінку в браузері після кожної зміни

### Завдання 2: Спробуй workflow (10 хв)

1. **Explore:** "Подивись що вже є в проєкті"
2. **Plan:** "Хочу додати секцію з трьома картками. Покажи план."
3. **Code:** "Ок, реалізуй" → перевір в браузері
4. **Iterate:** "Зроби картки з тінню і hover-ефектом"

Якщо встановив Cursor — спробуй також Ctrl+K (виділи заголовок → "зроби червоним") і Ctrl+L (чат з AI).

## Питання для самоперевірки

1. Ти хочеш створити нову сторінку з формою зворотного зв'язку. Що краще — Ctrl+K чи Claude Code?

2. Ти відкрив файл Header.tsx і хочеш змінити колір логотипу з синього на зелений. Ctrl+K чи Claude Code?

3. AI на Sonnet не справляється зі складною задачею — генерує код з помилками. Перше що варто спробувати...

4. Ти починаєш новий робочий день і відкриваєш Claude Code. Він одразу "знає" що це Next.js проєкт з Tailwind, бо...

5. Ти 5 промптів поспіль намагаєшся отримати правильний результат, AI кожен раз робить гірше. Найкращий наступний крок?
