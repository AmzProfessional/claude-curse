## Теорія

### Чому переходимо від HTML до фреймворку

У [[04-first-project|модулі 4]] ми зробили лендінг на чистому HTML. Для однієї сторінки — це ідеально. Але тепер ми будуємо MVP з кількома сторінками, навігацією, даними. І тут HTML починає "тріщати":

```
Еволюція проєкту:

Модуль 4 (лендінг):     Одна HTML-сторінка
                         ↓ все в одному файлі, працює чудово
                         
Модуль 6 (MVP):         5+ сторінок, навігація, дані, компоненти
                         ↓ потрібна структура і інструменти
                         
          HTML сам по собі → копіпаст, хаос, біль
          Фреймворк        → порядок, компоненти, швидкість
```

**Конкретна проблема:** уяви що у тебе 10 сторінок і на кожній однаковий header. Змінив логотип — міняй в 10 файлах. З фреймворком — змінив один раз, оновилось всюди.

| Проблема | HTML | Фреймворк (Next.js) |
|----------|------|---------------------|
| 10 сторінок з однаковим header | Копіпаст в кожен файл | Один компонент — використовується всюди |
| Навігація між сторінками | Перезавантаження сторінки | Миттєвий перехід |
| Зміна одного елемента | Змінюй в кожному файлі | Зміни в одному місці — оновлюється всюди |
| Дані з API | Складний JavaScript | Вбудований механізм |

**Важливо:** тобі не потрібно вчити Next.js. Claude Code знає його досконало. Тобі потрібно зрозуміти НАВІЩО ми його використовуємо і як описувати що ти хочеш.

### Next.js — Що це і навіщо

**Next.js** — це фреймворк на основі React для створення веб-додатків.

**Аналогія:** Якщо HTML — це цеглини, то Next.js — це конструктор LEGO. Цеглини (компоненти) стандартизовані і з'єднуються між собою.

**Що дає:**
- Маршрутизація (routing) — кожна папка = сторінка
- Компоненти — перевикористовувані блоки інтерфейсу
- Серверний рендеринг — сторінки швидко завантажуються
- Вбудована оптимізація зображень та шрифтів

**Не лякайся!** Тобі не потрібно розуміти як Next.js працює всередині. Claude Code знає це за тебе. Тобі потрібно знати:
- Як створити проєкт
- Як запустити його
- Як описати що ти хочеш

### Компоненти — будівельні блоки

Компонент — це окремий шматок інтерфейсу який можна перевикористовувати.

```
┌─── Layout ──────────────────────────┐
│ ┌─── Header ──────────────────────┐ │
│ │ Logo   NavLink  NavLink  NavLink│ │
│ └─────────────────────────────────┘ │
│ ┌─── Main Content ────────────────┐ │
│ │                                 │ │
│ │  ┌─ Card ─┐  ┌─ Card ─┐         │ │
│ │  │ Image  │  │ Image  │         │ │
│ │  │ Title  │  │ Title  │         │ │
│ │  │ Button │  │ Button │         │ │
│ │  └────────┘  └────────┘         │ │
│ │                                 │ │
│ └─────────────────────────────────┘ │
│ ┌─── Footer ──────────────────────┐ │
│ │ Links        Social    Copyright│ │
│ └─────────────────────────────────┘ │
└─────────────────────────────────────┘
```
![[будівельні блоки.png]]

**Компоненти які ми створимо:**
- `Header` — шапка сайту (з навігацією)
- `Footer` — підвал сайту
- `Layout` — обгортка (Header + контент + Footer)
- `Card` — картка (товару, послуги, тощо)
- `Button` — кнопка (різних стилів)

### Tailwind CSS — Стилізація без CSS-файлів

**Tailwind CSS** — це набір готових CSS-класів які ти додаєш прямо в HTML.

Замість написання CSS:
```css
.button {
  background-color: blue;
  color: white;
  padding: 8px 16px;
  border-radius: 8px;
}
```

Ти пишеш класи прямо в HTML:
```html
<button class="bg-blue-500 text-white px-4 py-2 rounded-lg">
  Натисни
</button>
```

**Для промптів це означає:**
```
Створи кнопку. Стилізація через Tailwind CSS:
синій фон, білий текст, заокруглені кути, тінь при hover.
```

### Структура Next.js проєкту

```
my-mvp/
├── app/                    ← Сторінки
│   ├── layout.tsx          ← Загальний layout
│   ├── page.tsx            ← Головна сторінка (/)
│   ├── about/
│   │   └── page.tsx        ← Сторінка "Про нас" (/about)
│   └── dashboard/
│       └── page.tsx        ← Дешборд (/dashboard)
├── components/             ← Компоненти
│   ├── Header.tsx
│   ├── Footer.tsx
│   └── Card.tsx
├── public/                 ← Статичні файли (зображення)
├── CLAUDE.md               ← Інструкція для AI
└── package.json            ← Залежності проєкту
```

**Ключове правило:** `app/назва-папки/page.tsx` = сторінка з URL `/назва-папки`

### Навігація між сторінками

В Next.js для навігації використовується компонент `Link`:

```jsx
import Link from 'next/link'

<Link href="/about">Про нас</Link>
<Link href="/dashboard">Дешборд</Link>
```

У промпті:
```
Додай навігацію в Header. Пункти меню:
- Головна (/)
- Про нас (/about)
- Дешборд (/dashboard)
- Контакти (/contacts)
Використовуй Next.js Link для навігації.
```

## Перевірка якості — як зрозуміти що результат ок

Після кожного кроку перевіряй не лише "чи працює", а й "чи якісно". Ось мінімальний чекліст:

**1. Браузер — основна перевірка:**
- Відкрий сторінку в браузері
- Клікни по кожному посиланню — чи працює?
- Прокрути вниз — чи все відображається?
- Зменш вікно до ширини телефону — чи не зламалось?

**2. DevTools (F12) — технічна перевірка:**
- Console — чи немає червоних помилок?
- Якщо є — скопіюй і покажи AI
- Network — чи немає failed-запитів (червоних)?

**3. Мобільна перевірка:**
- F12 → Toggle Device Toolbar (іконка телефону)
- Обери iPhone 14 або Galaxy S21
- Чи все читабельне? Чи не вилазить щось за межі екрану?

**4. Навігація:**
- Клікни кожен пункт меню — чи перехід працює?
- Натисни "Назад" — чи повертається?
- Відкрий URL напряму (не через навігацію) — чи працює?

**Правило:** якщо після кроку є 0 помилок в Console і всі посилання працюють — це ок для MVP.
