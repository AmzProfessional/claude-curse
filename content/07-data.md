## Теорія

### Чому статичні дані — це не MVP

В [[06-frontend|модулі 6]] ми захардкодили дані прямо в код. Це працює для демо, але не для реального продукту:

```
Захардкоджено:                  З файлу або бази:
Масив з 10 конкурентів           → Завантажив CSV з 500 записів
прямо в коді                     → Змінюєш дані без зміни коду
                                 → Оновлюєш щодня новими даними
                                 → Зберігаєш історію
```

### Робота з реальними файлами (CSV, Excel)

У реальній роботі дані приходять у файлах. Аналітик дає Excel, клієнт відправляє CSV, API повертає JSON. Потрібно вміти з цим працювати.

**CSV (Comma-Separated Values)** — найпростіший формат. Це текстовий файл де дані розділені комами:

```csv
asin,title,brand,price,bsr,revenue,date
B08N5WRWNW,Wireless Mouse,LogiTech,29.99,1523,45200,2026-05-05
B09XYZ1234,USB-C Hub,Anker,34.99,892,67800,2026-05-05
```

Будь-який Excel можна зберегти як CSV: Файл → Зберегти як → CSV.

**Приклад для Competitor Tracker:**
```
В мене є файл competitors.csv з такими колонками:
asin, title, brand, price, rating, reviews_count, bsr_rank, 
estimated_revenue, date

Файл містить дані 50 лістингів за 90 днів (4500 рядків).

Завантажити цей CSV в проєкт та:
1. Показати дані в таблиці на дешборді
2. Додати можливість завантажити новий CSV через форму upload
3. При завантаженні — парсити файл і оновлювати дані
```

**Як працювати з Excel через AI:**
```
В мене є Excel-файл report.xlsx з продажами.
Створи скрипт який:
1. Читає файл
2. Конвертує в JSON
3. Показує на веб-сторінці в таблиці з сортуванням
```

AI знає бібліотеки для роботи з Excel (SheetJS для JavaScript, openpyxl для Python). Тобі достатньо описати що потрібно.

### JSON — Універсальний формат даних

JSON (JavaScript Object Notation) — це формат запису даних який використовує весь інтернет.

```json
{
  "asin": "B08N5WRWNW",
  "title": "Wireless Mouse",
  "brand": "LogiTech",
  "price": 29.99,
  "bsr_rank": 1523,
  "estimated_revenue": 45200,
  "change_percent": 12.5
}
```

**Що потрібно знати:**
- `{}` — об'єкт (один запис)
- `[]` — масив (список записів)
- `"ключ": "значення"` — поле та його значення
- Числа без лапок: `"price": 29.99`
- true/false — логічні значення

### Локальні дані vs API vs База даних

| Підхід | Що це | Коли | Наш кейс |
|--------|-------|------|----------|
| **CSV/Excel файл** | Файл на диску | Дані приходять файлом, одноразовий аналіз | Початковий імпорт конкурентів |
| **Локальний JSON** | Файл в проєкті | Маленькі, рідко змінювані дані | Конфігурація, список ASIN |
| **API** | Зовнішній сервіс | Дані потрібні в реалтаймі | Amazon API, курси валют |
| **База даних** | Сховище | Дані змінюються, потрібна історія | Щоденні снепшоти конкурентів |

### Що таке API — простими словами

**API** — це спосіб отримати дані з іншого сервісу через інтернет.

**Аналогія:** API — це як офіціант у ресторані. Ти (клієнт) даєш замовлення (запит), офіціант (API) відносить його на кухню (сервер) та приносить їжу (дані).

```
Твій сайт  →  Запит: "Дай дані лістингу B08N5WRWNW"  →  Amazon API
Твій сайт  ←  Відповідь: { price: 29.99, bsr: 1523 }  ←  Amazon API
```

### Supabase — База даних без болю

**Supabase** — хмарна база даних з готовим API:

- Створюєш таблицю через веб-інтерфейс (як Excel)
- Автоматично отримуєш API для роботи з даними
- Безкоштовний план для MVP
- Claude Code вміє з ним працювати

**Для Competitor Tracker:**
- Таблиця `listings` — поточні дані конкурентів
- Таблиця `snapshots` — щоденні снепшоти (історія)
- Порівняння періодів = SQL-запит по snapshots

### CRUD — Чотири операції з даними

| Операція | Що робить | Наш приклад |
|----------|-----------|-------------|
| **C**reate | Створити | Завантажити нові дані з CSV |
| **R**ead | Прочитати | Показати таблицю конкурентів |
| **U**pdate | Оновити | Оновити ціну лістингу |
| **D**elete | Видалити | Прибрати лістинг з моніторингу |

### Безпека даних — базові правила

Перед тим як працювати з реальними даними — запам'ятай три правила:

```
🔴 НІКОЛИ НЕ КОМІТИТИ:
───────────────────────
• .env, .env.local — API ключі, токени, паролі
• credentials.json — сервісні акаунти
• *.pem, *.key — сертифікати та ключі
• Файли з реальними даними клієнтів
• Файли з паролями, токенами, секретами

🟢 ЯК ПРАВИЛЬНО:
─────────────────
• Ключі в .env.local → додай .env.local в .gitignore
• Створи .env.example з назвами змінних БЕЗ значень
• Реальні дані клієнтів — НЕ в репозиторії
• Тестові дані — ок, реальні — ні
```

**Перевірка:** перед кожним `git push` — подивись `git diff` і переконайся що там немає ключів чи паролів.

**Якщо випадково закомітив секрет:**
1. Зміни ключ/пароль одразу
2. Видали з коду
3. Додай файл в .gitignore
4. Закомітиь виправлення

Не достатньо просто видалити файл в новому коміті — він залишиться в git-історії. Тому **міняй ключ**.

## Практика

**Наскрізний приклад:** Підключаємо реальні дані до Competitor Tracker. Починаємо з CSV файлу, потім переходимо на Supabase.

### Крок 1: Робота з CSV (15 хв)

```
Створи тестовий CSV-файл data/competitors.csv:
- 50 лістингів Amazon
- Колонки: asin, title, brand, price, rating, reviews_count, 
  bsr_rank, estimated_revenue, date
- Дані за останні 7 днів (50 × 7 = 350 рядків)
- Реалістичні дані з невеликими щоденними змінами
- 3-5 лістингів з аномальними змінами (>20%)

Потім:
1. Створи сторінку app/upload/page.tsx з формою upload CSV
2. При завантаженні — парсити CSV і показувати preview даних
3. Кнопка "Імпортувати" зберігає дані в стейт
4. Дешборд (app/page.tsx) показує імпортовані дані
```

### Крок 2: Підключи Supabase (15 хв)

1. Зареєструйся на https://supabase.com
2. Створи новий проєкт
3. Скопіюй URL та anon key з Settings → API

```
Підключи Supabase до Competitor Tracker:
URL: [твій URL]
Anon Key: [твій ключ]

1. Встанови @supabase/supabase-js
2. Створи lib/supabase.ts з клієнтом
3. Зберігай ключі в .env.local
4. Додай .env.local в .gitignore
5. Створи .env.example з пустими значеннями
```

### Крок 3: Таблиці та імпорт (10 хв)

```
Створи SQL для Supabase:

1. Таблиця listings:
   - id (auto), asin (text), title (text), brand (text)
   
2. Таблиця snapshots:
   - id (auto), listing_id (FK), price (decimal), 
     rating (decimal), reviews_count (int), bsr_rank (int), 
     estimated_revenue (decimal), date (date)

3. Створи функцію імпорту — завантажений CSV 
   зберігається в ці таблиці
```

### Крок 4: Дешборд з реальними даними (10 хв)

```
Оновити дешборд (app/page.tsx):
1. Завантажувати дані з Supabase замість захардкоджених
2. Показувати loading стан поки дані завантажуються
3. Показувати повідомлення "Немає даних — завантажте CSV"
4. Рахувати change % порівняно з попереднім днем

Дані з Supabase таблиць listings + snapshots.
```

### Крок 5: Git (5 хв)

```bash
git add .
git commit -m "Connect Supabase, add CSV import and real data to dashboard"
```

**Перевір перед комітом:** `git diff` — чи немає API ключів в коді?

## Перевірка якості

Після кожного кроку перевір:

| Що перевірити | Як | Очікуваний результат |
|---------------|-----|---------------------|
| CSV парситься | Завантаж тестовий файл | Дані з'являються в preview |
| Supabase працює | Відкрий дешборд | Дані з бази відображаються |
| Завантаження CSV → база | Імпортуй CSV | Дані з'являються на дешборді |
| Секрети захищені | `git diff` | .env.local в .gitignore, ключів в коді немає |
| Помилки | Відкрий Console (F12) | Немає червоних помилок |
