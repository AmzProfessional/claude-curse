# Модуль 0: Що таке вайбкодинг

> **Тривалість:** 30 хв теорія + 15 хв демо
> **Результат:** Розуміння підходу, мотивація, реалістичні очікування

---

## Теорія

### Як раніше створювались продукти

Щоб зрозуміти що змінилось — подивись як було до цього. Кожен програмний продукт проходить один і той самий цикл з 6 етапів — SDLC (Software Development Life Cycle):

```
┌──────────────┐     ┌──────────┐     ┌────────────────┐
│ Requirements │ ──→ │  Design  │ ──→ │ Implementation │
│   Продакт    │     │ Архітект │     │  Розробники    │
└──────────────┘     └──────────┘     └───────┬────────┘
                                              │
┌──────────────┐     ┌────────────┐   ┌───────▼───────┐
│ Maintenance  │ ←── │ Deployment │ ←─│    Testing    │
│   Support    │     │   DevOps   │   │      QA       │
└──────────────┘     └────────────┘   └───────────────┘

         Стандартна команда: 10-50 людей
```

**Приклад:** Коли Instagram запускався у 2010 році, навіть мінімальну версію робила команда з 13 людей. Продакт-менеджер збирав вимоги, дизайнер малював макети, розробники писали код (окремо фронтенд і бекенд), QA тестував, DevOps налаштовував сервери. Це зайняло 8 місяців і коштувало $500K венчурних інвестицій.

Хочеш зробити MVP дешборду аналітики? У класичній моделі — 3-6 місяців, $50-200K, мінімум 5 людей.

### Етап 1: Вайбкодинг змінив правила (2025)

У лютому 2025 **Andrej Karpathy** (один з засновників OpenAI) описав новий підхід:

> "There's a new kind of coding I call 'vibe coding', where you fully give in to the vibes, embrace exponentials, and forget that the code even exists."

Що змінилось — AI взяв на себе **написання коду** і **частково тестування**:

```
┌──────────────┐     ┌──────────┐     ┌────────────────┐
│ Requirements │ ──→ │  Design  │ ──→ │ Implementation │
│   людина     │     │  людина  │     │  🤖 AI ПИШЕ     │
└──────────────┘     └──────────┘     └───────┬────────┘
                                              │
┌──────────────┐     ┌────────────┐   ┌───────▼───────┐
│ Maintenance  │ ←── │ Deployment │ ←─│    Testing    │
│   людина     │     │   людина   │   │  🤖 AI частк . │
└──────────────┘     └────────────┘   └───────────────┘

      AI автоматизував ~2 з 6 етапів (~33%)
```

Результат: одна людина може написати MVP за дні, а не за місяці. Але дизайн, деплой, підтримку — все ще робиш сам вручну.

**Цей курс навчить тебе саме цьому підходу** — вайбкодингу. Ти описуєш що хочеш, AI пише код, ти перевіряєш і ітеруєш.

### Етап 2: Оркестрація агентів — одна людина = команда (2026)

Зараз, у 2026, з'явився наступний рівень — **AI-агенти закривають всі 6 етапів**:

```
┌──────────────┐     ┌──────────┐     ┌────────────────┐
│ Requirements │ ──→ │  Design  │ ──→ │ Implementation │
│  🤖 агент     │     │ 🤖 агент  │     │  🤖 агенти      │
│  збирає і    │     │ обговорює│     │  пишуть код    │
│  формалізує  │     │  підхід  │     │   хвилями      │
└──────────────┘     └──────────┘     └───────┬────────┘
                                              │
┌──────────────┐     ┌────────────┐   ┌───────▼───────┐
│ Maintenance  │ ←── │ Deployment │ ←─│    Testing    │
│   🤖 агент    │     │  🤖 агент   │   │  🤖 агенти     │
│  моніторить  │     │  публікує  │   │  перевіряють  │
│  і фіксить   │     │ в інтернет │   │  якість       │
└──────────────┘     └────────────┘   └───────────────┘

  Одна людина керує агентами. Всі 6 етапів автоматизовані.
```

Фреймворк **GSD (Get Shit Done)** — 61 000+ зірок на GitHub — вже реалізує цей підхід. Одна людина ставить задачу, агенти самостійно проходять весь цикл розробки.

**Це вже працює.** Pieter Levels — один розробник з ноутбука на Балі — заробляє $3M+ на рік з нульовою командою. Maor Shlomo соло побудував Base44, набрав 250 000 юзерів, і компанію купила Wix за $80M.

**Важливо:** ми не будемо вчити оркестрацію агентів у цьому курсі — це просунутий рівень. Але ми навчимо тебе фундаменту: вайбкодинг, MCP, Skills. Це база, без якої агентна оркестрація не працює. І якщо тебе зацікавить — знатимеш куди рости далі.

### Де межа — чого одна людина не зробить

Будьмо чесні:

| Що реально соло | Що потребує команду |
|-----------------|---------------------|
| MVP, прототип, внутрішній інструмент | Банківська система, медичний софт |
| Дешборд аналітики, бот, автоматизація | Навантаження на мільйон юзерів |
| Лендінг, SaaS на 1000 юзерів | Юридична відповідність (GDPR, PCI) |
| Швидка перевірка ідеї | Складна інфраструктура 24/7 |

45% AI-генерованого коду має вразливості. Для серйозного масштабування потрібні інженери. Для MVP — достатньо тебе, ноутбука та Claude.

### Що таке вайбкодинг

**Вайбкодинг (vibe coding)** — створення програм через розмову з AI, без написання коду вручну. Ти описуєш що хочеш отримати — AI пише код за тебе. Якщо вмієш написати ТЗ — вмієш вайбкодити.

### Чому це працює зараз

1. **AI став достатньо розумним** — Claude Sonnet, Claude Opus та сучасні AI-моделі генерують робочий код з текстового опису
2. **Інструменти стали доступними** — Claude Code, Cursor — все працює прямо зараз
3. **Поріг входу знизився** — не потрібні роки навчання для створення робочих продуктів

### Що можна створити через вайбкодинг?

| Тип проєкту   | Приклад                                 | Складність |
| ------------- | --------------------------------------- | ---------- |
| Лендінг       | Сторінка продукту або послуги           | Легко      |
| Портфоліо     | Особистий сайт з роботами               | Легко      |
| Веб-додаток   | Таск-трекер, калькулятор, дешборд       | Середньо   |
| Бот           | Telegram-бот для команди                | Середньо   |
| Автоматизація | Скрипт обробки даних з Excel            | Середньо   |
| SaaS MVP      | Мінімальний продукт для тестування ідеї | Складно    |

### AI як напарник, а не інструмент

Ключова різниця вайбкодингу від "просто копіювання коду з ChatGPT":

- **Інструмент** — ти питаєш, він відповідає, ти копіпастиш і молишся що працює
- **Напарник** — ти описуєш ціль, він створює, ти направляєш, він ітерує

Ми працюватимемо з AI як з напарником:
- Даємо контекст проєкту
- Описуємо що хочемо
- Перевіряємо результат
- Просимо виправити або покращити
- Повторюємо поки не задоволені

### Ітеративний підхід — головна суперсила

Ось ключове, що відрізняє вайбкодинг від "замовити сайт у фрілансера":

**Ти можеш робити нескінченну кількість версій.** Безкоштовно. За хвилини.

```
Версія 1: Базова сторінка → перевірив → не те
Версія 2: Змінив структуру → перевірив → краще, але кнопка не та
Версія 3: Виправив кнопку → перевірив → готово
```

Це як Google Docs з історією версій, тільки для цілого продукту. Зламав щось? Відкотився. Хочеш спробувати іншу ідею? Зробив бранч, потестив, не сподобалось — видалив.

**Принцип роботи:**
1. Збудував MVP
2. Подивився як працює
3. Вибрав ОДИН компонент для покращення
4. Покращив, протестував
5. Перейшов до наступного компонента
6. Повторюй поки не задоволений

Не намагайся зробити все ідеально з першого разу. Ніхто так не робить — навіть Google випускає продукти в beta і допрацьовує місяцями. Ти просто робиш це в масштабі одного вечора.

### Обмеження — чого НЕ може вайбкодинг

Будьмо чесні з самого початку:

1. **Не замінює програмістів** — складні системи, високонавантажені сервіси, критична інфраструктура потребують глибоких знань
2. **Потрібно розуміти ЩО ти хочеш** — AI не вигадає за тебе продукт, він реалізує твоє бачення
3. **Код може мати баги** — потрібно тестувати результат
4. **Безпека** — не варто будувати банківські системи через вайбкодинг
5. **Масштабування** — MVP це добре, але продакшн-систему на мільйон юзерів потрібно робити з інженерами

### Наскрізний проєкт курсу: Amazon Competitor Tracker

Щоб навчання було конкретним, ми будемо будувати **один реальний проєкт через весь курс** — інструмент моніторингу конкурентів на Amazon.

**Що це:**
- Дешборд який збирає дані 50 конкурентних лістингів
- Порівнює показники: вчора/тиждень/місяць
- Знаходить аномалії (різке зростання, падіння)
- Генерує звіти та сповіщення

**Чому саме цей проєкт:**
- Вирішує реальну задачу (аналітики витрачають години на ручний моніторинг)
- Проходить через всі модулі курсу: лендінг → фронтенд → дані → автоматизація → деплой
- Має зрозумілу бізнес-цінність — можна показати і пояснити навіщо
- Достатньо складний щоб навчитись, достатньо простий щоб зробити

Ти можеш робити свій проєкт замість цього — але Amazon Tracker завжди буде як приклад: "ось так це виглядає крок за кроком".

### Що ми надаємо

Для проходження курсу вам не потрібно нічого купувати самостійно:

- **Підписка на Claude** — ми надаємо доступ до Claude Pro (працює в Claude Code та Cursor)
- **Хостинг та сервер** — надаємо доступ для деплою ваших проєктів

Все що потрібно від тебе — ноутбук і бажання створювати.

## Демо

### Що побачимо на демо

Інструктор (або відео) показує:

1. Відкриття Cursor
2. Запуск Claude Code в терміналі
3. Запит: "Створи просту HTML-сторінку з привітанням та кнопкою, яка змінює колір фону"
4. Claude Code створює файл
5. Відкриваємо в браузері — працює!
6. Просимо додати анімацію — Claude Code дописує код
7. Готово за 2 хвилини

**Ключовий меседж:** те, на що раніше потрібно було кілька годин вивчення HTML/CSS/JS — тепер робиться за 2 хвилини розмови. І якщо результат не сподобався — ще 30 секунд на виправлення.
